# True fusion: Termux's prefix transformed into a Debian arm64 system

> [!CAUTION]
> **One-way, experimental, and far less safe than `main`.** `main` installs
> Debian into its own prefix (`~/.dn`) beside Termux: a bad package breaks
> only that prefix, deleting it restores Termux exactly, and Termux keeps
> its repos and updates. True fusion installs Debian packages *into
> Termux's own `$PREFIX`*, sharing Termux's dpkg database, and every Debian
> maintainer script runs with write access to Termux's live system. The
> worst case is not "a Debian program fails" but "Termux itself breaks";
> near misses already hit in testing: `awk` broken system-wide by a `mawk`
> reinstall, `main`'s runtime setup about to overwrite Termux's own
> `chown`/`chgrp`/`update-alternatives`, and doubled
> `$PREFIX/data/data/...` paths from `update-alternatives`/`dpkg-divert`.
> Protection here is guards (floor guard, collision check, pins, holds),
> not separation. There is no switch back: the backup restores dpkg/apt
> state, not every file packages wrote into `$PREFIX`, and Termux's floor
> packages (`apt`, `openssl`, `curl`, glibc) get no updates, security
> fixes included, until phase 3. Use `main` unless you want exactly this
> trade, and only on a device/Termux install you can wipe.

Experiment on the `naibed` branch, which absorbs the earlier
`fusion-no-prefix` branch and its history.
Termux's own prefix is transformed, **one way**, into a Debian `arm64`
system: Debian becomes apt's only source, Debian packages are installed
straight into `$PREFIX` through the pipeline `main` built (repack,
maintainer-script patching, ELF patching, launchers, the path shim), and
Termux packages other than the floor may be replaced by Debian's. There is
no switch back; the backup archive is the only undo.

## Roadmap

1. **Make Debian run smoothly** on the transformed prefix (now).
2. **Replace** non-floor Termux packages with Debian's (crossgrades).
3. **Add Termux's repos back as the secondary supply**, forced to follow
   Debian's multiarch rules: the roles are switched -- Termux's packages
   have to fit the transformed system, not the other way round. Termux's
   sources are kept aside for this in `$PREFIX/etc/deb-native/termux-sources/`.
   Until then the floor gets no updates.

## Why not coexistence

Measured on a real device (Termux dpkg 1.22.6 / apt 2.8.1, `aarch64`
native + `arm64` foreign), mostly as `apt-get -s` against a *copy* of
Termux's status and a real Debian stable `arm64` index:

1. **dpkg keys packages by name.** A second architecture of the same name
   can only be co-installed when *both* are `Multi-Arch: same` and every
   shared file is byte-identical. Otherwise installing `foo:arm64` silently
   **crossgrades** `foo:aarch64` away (`Remv jq`, `Remv perl`). Termux ships
   no `Multi-Arch` fields, and 914 package names exist in both archives (74
   of them installed on the test device).
2. **`Architecture: all` means native.** About half of Debian (33,690 of
   68,196 packages) is `all`, which apt/dpkg treat as the *native*
   architecture -- Termux's side. Rewriting `all` -> `arm64` fixes that,
   but only exposes (1) at full scale.
3. Solving (1) inside one shared name space means renaming ~900 packages
   and every relation to them, and relocating their files.

A reversible "Debian mode" (switchable apt sources) was built first and
works, but still has to keep every Termux package untouched. True fusion
drops that: one system, Debian's rules, Termux reduced to its floor.

## Package tiers

| Tier | What | Source | Protection |
|---|---|---|---|
| 0. Floor | Termux's `Essential: yes` packages and everything they depend on: 117 of 260 on the test device (`apt`, `dpkg`, `bash`, `dash`, `coreutils`, `gawk`, `termux-exec`, `termux-tools`, `termux-am`, the glibc stack, `openssl`, `ca-certificates`, `libcurl`, ...). What the Termux app, apt and dpkg run on | Termux (no updates until phase 3) | `dn-floor.sh`, snapshotted once to `$PREFIX/var/lib/deb-native/floor`; the plan guard refuses any apt run that removes or crossgrades one. apt also refuses to remove `Essential` packages |
| 1. Termux-backed identity | Debian names a floor package fills: `libc6` (built), `dn-dash`, `dn-openssl`, `dn-ca-certificates` | generated by `dn-base-env.sh` from the installed Termux package | Debian's originals pinned to `-1` |
| 2. Debian base, customized, frozen | `base-files`, `base-passwd`, `debconf`, `cdebconf`, `mawk` -- what makes every other package see "Debian" (`main`'s `bootstrap-base.sh` set) | Debian, through the pipeline, plus `scripts/fusion-custom/<package>.sh` | `apt-mark hold` after install; refreshed only deliberately |
| 3. Packages | everything else, including replacements for the 143 non-floor Termux packages | Debian, through the pipeline | normal apt |

Tier 1 naming: an identity package must not share a name with an
installed Termux package, or installing it crossgrades Termux's copy away.
`libc6` keeps Debian's name because Termux has no `libc6`; the others are
`dn-NAME` with `Provides: NAME (= <termux version>)`. `openssl` means
different things: Termux's `openssl` is the library (floor), Debian's is
the CLI; Debian's library is `libssl3t64` and comes from Debian.

Tier 2 uses a hold, not a version pin: Debian stable drops superseded
versions from its index at every point release, and a pin to a version
that has left the index stops holding silently. The cost is strictness: a
package needing a newer base (`debconf (>= X)`) is refused with a "held
packages" error until the base is refreshed.

### libc6 is the one package that cannot come from Debian

Debian's own `libc6` (glibc 2.41) through its own `ld.so` kills every
binary at startup with `SIGSYS` (exit 159; `strace`:
`si_syscall=__NR_set_robust_list`) -- Android's app seccomp filter. The
same `hello` runs under Termux's glibc. Termux's glibc
(`termux-pacman/glibc-packages`, `gpkg/glibc/`) is Debian's libc
translated for Android **at the source level**, ~50 patches:
`set-nptl-syscalls.patch` (drops `set_robust_list`), `disable-clone3`,
`disable-termios2`, `fakesyscall.json` (blocked syscalls mapped to allowed
ones; `setuid*`/`setgid*` return 0), SysV `shm*`/`sem_open` emulation,
Android passwd/group NSS, `set-dirs.patch`. None of it is reachable from
outside `libc.so.6`. `grun` is ~280 lines of bash that only unsets
`LD_PRELOAD`, prepends `$PREFIX/glibc/bin`, runs `patchelf`
(`--configure`) and optionally preloads `libtermux-exec-glibc.so`.

### libc6:arm64 identity package

A real package named `libc6`, `Architecture: arm64`, `Multi-Arch: same`,
installed with `dpkg -i`, whose files are symlinks at Debian's `libc6`
paths into Termux's glibc:

```
lib/aarch64-linux-gnu/libc.so.6              -> ../../glibc/lib/libc.so.6
lib/aarch64-linux-gnu/ld-linux-aarch64.so.1  -> ../../glibc/lib/ld-linux-aarch64.so.1
lib/aarch64-linux-gnu/gconv                  -> ../../glibc/lib/gconv
lib/ld-linux-aarch64.so.1                    -> aarch64-linux-gnu/ld-linux-aarch64.so.1
```

- File list from Debian's real `libc6.deb`, matched **by soname** against
  `$PREFIX/glibc/lib`.
- Debian binaries get one library directory (`$PREFIX/lib/aarch64-linux-gnu/`,
  Debian's libraries next to libc) and one loader path
  (`$PREFIX/lib/ld-linux-aarch64.so.1`); the repack step points every ELF there.
- **Version = Termux's real glibc version** (`2.44-0dn1`), so
  `libc6 (>= X)` keeps telling the truth; upgrades to Debian's own `libc6`
  are blocked by the pin. (A pin needs arch-qualified names: a bare
  `libc6` in a preferences file only matches the native architecture.)

## The transformation: `scripts/dn-fuse.sh`

Idempotent, one way:

1. Snapshot the floor (`dn-floor.sh`) before anything changes.
2. Move Termux's `sources.list` and `sources.list.d/*` to
   `$PREFIX/etc/deb-native/termux-sources/` (phase 3).
3. `$PREFIX/etc/apt/sources.list` = Debian stable `main` (+ updates,
   security), `[trusted=yes arch=arm64]` like `main`'s prefix (Termux has
   no Debian keyring -- a known gap inherited from `main`). Tier-1 pins in
   `preferences.d/deb-native`; the pipeline in `apt.conf.d/99-deb-native`:
   no Recommends (as `main`'s `apt-install.sh`; Recommends pull XS perl
   modules that need Debian's perl), no pdiffs, `--instdir=$PREFIX`,
   `--force-script-chrootless`, the hooks below.
4. Launchers first on `PATH` via `etc/profile.d/deb-native.sh`; a `pkg`
   launcher that refuses (Termux's `pkg` rewrites apt's sources).
5. `apt update` (the `all` -> `arm64` index rewrite runs after it), then
   `dn-base-env.sh`.

### Index translation: `Architecture: all` -> `arm64`

`dn-debian-index.sh` rewrites every `binary-arm64_Packages` list after each
`apt update`, so Debian's `all` packages live on the `arm64` side and
resolve against Debian. The `.deb` hashes stay the originals (download
verification still checks them); the repack step rewrites each `.deb`'s
control file by the same rule so apt and dpkg agree.

## Base environment: `scripts/dn-base-env.sh`

1. `arm64` as a dpkg foreign architecture.
2. `$PREFIX/usr -> .`, so Debian's `/usr/...` paths resolve into the flat
   prefix.
3. `main`'s own `setup-runtime.sh`, placed by `dn-layout.sh` (below), and
   `bin/dn-shell`, `bin/dn-perl` links so the shim's `#!/bin/sh` /
   `#!/usr/bin/perl` mapping to `$INSTDIR/usr/bin/dn-*` resolves unchanged.
4. The `libc6:arm64` identity package.
5. Tier-1 stand-ins `dn-dash`, `dn-ca-certificates` (links
   `etc/ssl/certs/ca-certificates.crt`), `dn-openssl` (links
   `lib/ssl/{cert.pem,certs,openssl.cnf}`, where Debian's `libssl3t64`
   looks).

### Reusing main, not re-deriving it

| main (`setup-apt-prefix.sh` and what it calls) | true fusion |
|---|---|
| shim, `setup-runtime.sh` (`dn-run`, tracer, `dn-shell`/`dn-perl`, no-op `chown`/`chgrp`/`dpkg-statoverride`, `update-alternatives` wrapper) | same script; plus a `dpkg-divert` wrapper (same double-prefix bug as `update-alternatives`: under `DPKG_ROOT` it opens `$PREFIX$PREFIX/var/lib/dpkg/diversions`) |
| `native-seed.sh` | only `libc6` bridged, as a real package; other libraries from Debian |
| `patch-deb.sh`, `patch-elfs.sh` (`grun --configure`) | `patch-deb.sh` as-is; the ELF edit moved into the repack step (before any maintainer script runs), pointing at the identity paths |
| `bootstrap-base.sh` | tier 2, via apt, with `fusion-custom/` changes |
| `make-launchers.sh` | same script, scoped to the new packages' own programs (`DN_LAUNCH_FILES`); launchers export `DN_INSTDIR`, `dn-run`'s existing override |
| `make-apt-wrappers.sh` ("Termux wins" routing) | not used: one supply |

**Layout rule** (`dn-layout.sh`, sourced by `setup-runtime.sh`,
`patch-deb.sh`, `patch-maintainer-scripts.sh`, `make-launchers.sh`): when
INSTDIR is Termux's own prefix, `usr/bin` *is* Termux's `bin/`, so `main`'s
runtime files would replace Termux's binaries (the no-op `chown`/`chgrp`
over coreutils', the `update-alternatives` wrapper over the binary it
execs). They go to `$PREFIX/lib/deb-native/` and `.../fusion-bin/`, which
`dn-launch` puts first on a maintainer script's `PATH` (after it, Termux's
glibc tools, then Termux's Bionic `bin/`: a Bionic child never gets the
shim). The classic layout is unchanged.

## Install pipeline (apt hooks)

| Hook | Step | Script |
|---|---|---|
| `DPkg::Pre-Install-Pkgs` (protocol v3: apt's full plan) | **floor guard**: refuse any run that removes or crossgrades a floor package; only `arm64` may be installed | `dn-hook-pre.sh` |
| same, per `.deb` | usr/ merged into the flat prefix (merged-/usr links dropped), `fusion-custom/<pkg>.sh`, `all` -> `arm64`, ELFs repointed (interpreter + `RUNPATH` first entry `$PREFIX/lib/aarch64-linux-gnu`, shared libraries too) | `fuse-repack.sh` |
| same | refuse a file collision, except the package's own `:arm64` files and files of a Termux package this run crossgrades | `fuse-classify.sh` |
| same | maintainer-script shebangs -> `dn-shell` | `patch-deb.sh` |
| `DPkg::Post-Invoke` | normalize exactly the symlinks the new packages and their alternatives brought in; launchers for their `bin`/`sbin`/`games` programs; drop stale launchers | `dn-hook-post.sh`, `normalize-symlinks.sh` (`NORMALIZE_LINKS_FILE`), `make-launchers.sh` |

### Known risk for phase 2

A replaced program becomes a glibc binary at `$PREFIX/bin/x`. Termux's
Bionic side passes its `termux-exec` preload to every child, and a glibc
program started with it dies at load (`libc.so: invalid ELF header`).
Launchers first on `PATH` cover a program started by name, not one a floor
program runs by full path. To investigate before crossgrading: whether
`termux-exec` can drop its preload when exec'ing a glibc program.

## Verified on the test device

- (Debian mode, 2026-09-26) `libc6:arm64 2.44-0dn1`: 25 paths, no dangling
  link; Debian's `libc6` at `-1`; `apt-get check` clean; Debian's `hello`
  runs through the identity paths.
- Floor guard (as the earlier all-Termux guard): `apt-get install jq:arm64`
  refused (`jq:aarch64(remove)`), Termux's `jq` untouched.
- `sl` installed through the pipeline: `ld.so --list` resolves Debian's
  ncurses in `lib/aarch64-linux-gnu` and libc through the identity links;
  run by name from a login shell (launcher -> `dn-run` -> shim) it draws
  the train, and ncurses reads Termux's terminfo through the shim.
- Tier 1: `dn-dash`, `dn-openssl`, `dn-ca-certificates` installed; Debian's
  `dash`, `openssl`, `ca-certificates` have no candidate.
- `dn-fuse.sh` run (2026-09-27): floor 117 packages; Termux's
  `sources.list` and `glibc.list` moved to `etc/deb-native/termux-sources/`;
  apt reads only Debian.
- Tier 2 installed through the pipeline and held: `base-files`,
  `base-passwd`, `debconf`, `cdebconf` (+ 9 Debian libraries), `mawk`.
  `base-files` needed `fusion-custom/base-files.sh` (merged-/usr check
  inverted; its merged-/usr links dropped by the repack step). It ran in
  its earlier variant, which left Termux's `var/run` in place (the
  `var/run` -> `run` move only runs on a first install), so `var/run` is
  still Termux's directory. `etc/passwd`/`group` created by `base-passwd`;
  `debconf-communicate` answers. DEP17 diversions landed in
  `$PREFIX/var/lib/dpkg/diversions` through the `dpkg-divert` wrapper.
  (`apt-get install --reinstall` of a held package drops the hold;
  re-running `dn-base-env.sh` restores it.)
- Incident: reinstalling `mawk` broke `awk`. `update-alternatives` wrote
  absolute links (`bin/awk -> /etc/alternatives/awk -> /bin/gawk`), and
  the post hook that rewrites them runs `awk`. Fixed by
  `dn-fix-alternatives.sh` (Termux's `gawk` by full path), run by the
  fusion `update-alternatives` wrapper right after each call. Two more
  double-prefix leaks found on the way: `update-alternatives` joins
  `DPKG_ROOT` onto an explicit `--log` too (wrapper now passes
  `/var/log/alternatives.log` with `DPKG_ROOT` set), and the stray
  `$PREFIX/data/data/com.termux/...` tree it had left was removed. Re-test:
  `awk` stays `gawk` 5.3.0 throughout, links relative.
- Run by name from a login shell: `hello`, `lua5.4`, `ncdu`, `sl`,
  `banner`, `mawk`, and `figlet` -- an alternatives link, which needed a
  launcher of its own (the post hook now adds launchers for alternatives
  links whose program an `arm64` package owns). Without one it failed
  exactly as the phase-2 risk predicts: `libc.so: invalid ELF header`.
- `apt-get check` clean; 28 `arm64` packages installed.

## Backup

Before the first change the whole Termux package state was archived on the
device: `~/dn-fusion-backup/termux-pkgstate-<ts>.tar.gz` (+ `.sha256`,
`MANIFEST-<ts>.txt`) -- `etc/apt`, `etc/termux`, `etc/alternatives`,
`var/lib/dpkg`, `var/lib/apt`. It restores package state, not files
Debian packages have since written into the prefix.
